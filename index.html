SeaClear 2.0

Mapping is how the grapple knows where to go

Litter on the seafloor is hard to find and harder to pick up. Water visibility can be poor, sonar is noisy, and a recovery robot needs a coordinate it can act on, not just an image. SeaClear 2.0 is an EU-funded consortium coordinated by TU Delft, and my group at the Technical University of Cluj-Napoca works on the mapping.

I built the C++/ROS 2 pipeline that turns camera and sonar detections into a 3D map, clusters them into objects, and serves their GPS coordinates to TU München's grapple system for autonomous retrieval. Latency-critical ray-casting runs in C++. Detection, sensor bridging, georeferencing and operator services run in Python, so we can change them quickly in the field.

  1. Sense

    Oculus multibeam sonar, IP camera, Waterlinked A50 DVL, IMU and SBL acoustic positioning, with EKF-fused odometry.

  2. Detect

    ONNX inference on live camera and sonar streams, with an auto/manual mode service for operators.

  3. Map

    Occlusion-aware ray-casting into a 3D OctoMap, in C++.

  4. Locate

    Clustering into litter objects, georeferenced from ENU to WGS84.

  5. Retrieve

    GPS coordinates served to the grapple for autonomous pickup.

Selected work

What I've built

Camera and sonar mapping

The core detection-to-map pipeline: camera and sonar detections projected into a 3D OctoMap, clustered and served as GPS coordinates. Evaluated with Python tooling (NumPy, rosbag2 replay, pymap3d) against GPS-surveyed ground truth.

C++ · ROS 2 · OctoMap · Python

Active mapping with camera-sonar fusion

A forward-looking sonar and a camera feed one shared Bayesian occupancy map, and at each step an optimization picks the next best view, balancing exploration of uncertain regions against confirmation of likely objects. Each sensor is modeled with range- and bearing-dependent detection and false-alarm tables determined from data. In a realistic underwater simulator, active mapping found objects faster than a lawnmower pattern, and using both sensors worked better than either alone. Paper

Next best view · Bayesian occupancy mapping · Simulation

Probabilistic mapping and active search

Log-odds occupancy mapping of sonar detections, plus an information-driven next-best-view planner with sonar footprint, geofence and bathymetry safety constraints. Validated in closed-loop simulation.

Planning · Occupancy mapping · Simulation

Perception and operator tooling

Python inference nodes running ONNX models on live streams, Foxglove Studio bridges, live voxel-map visualization and image-annotation panels, so operators can watch the map and mark objects during a mission.

ONNX Runtime · Foxglove · rclpy

Debugging on the water

Failures that only show up at sea, fixed during live trials: a TF frame race that mirrored sonar detections, a Fast DDS shared-memory transport issue between Docker containers, a bounding-box scaling bug in detection post-processing, and many more.

TF2 · Fast DDS · Docker

BlueROV2 platform for underwater mapping

A low-cost lab platform for developing and validating underwater mapping, with the ROV and test objects in a pool imaged by an overhead camera. Pose comes from extended Kalman filtering of overhead-camera, inertial and pressure measurements, and a deep neural network detects litter in the ROV camera stream. Code · Paper

ROS · EKF · YOLO · Python

LQR control for a BlueROV2

My BSc thesis: LQR stabilization and trajectory tracking for a BlueROV2, implemented and validated in MATLAB/Simulink.

Control · MATLAB/Simulink
